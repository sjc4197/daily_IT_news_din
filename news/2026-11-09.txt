title: Claude Code '다시 묻지 않기' 설정 파일로 GitHub 공개 저장소 1,122곳에 비밀번호·키 노출
category: IT
importance: 5
source: The Hacker News
url: https://thehackernews.com/2026/11/claude-codes-dont-ask-again-file.html
summary: Claude Code가 승인한 셸 명령을 .claude/settings.local.json에 평문 저장하면서, 공개 저장소에서 DB 비밀번호·SSH 계정·클라우드 키 등 1,379개 비밀이 발견됐다.
detail: 보안업체 Apiiro 조사에 따르면 Claude Code에서 셸 명령에 "Yes, and don't ask again"을 고르면 명령 전체가 비밀번호·토큰까지 포함된 채 .claude/settings.local.json에 평문으로 저장될 수 있다.
- 이 파일은 사용자 전역 git excludes에는 추가되지만 프로젝트 .gitignore에는 들어가지 않아, 이미 커밋된 경우 보호되지 않는다.
- GitHub 공개 저장소 103,617곳에서 파일 104,185개를 찾았고, 그중 1,122개에 비밀 1,379개가 들어 있었다. DB 비밀번호 379개, SSH 로그인 43개, GitHub/GitLab/npm 토큰 42개, AWS 키 23개 등이다.
- 과거 커밋·포크·공유 설정 파일·채팅 로그까지 합치면 저장소 1,994곳에서 비밀 2,539개가 확인됐다.
- gitleaks와 TruffleHog 모두 215개를 놓쳤는데, 명령어 안에 직접 친 비밀번호는 키 형식이 아니라 스캐너가 잡지 못하기 때문이다.
- 관련 버그 리포트는 자동화 봇이 "not planned"로 닫았고 Anthropic의 답변은 없었다고 연구진은 밝혔다.
권고 사항은 노출된 자격증명 즉시 교체, git rm --cached로 추적 해제 후 .gitignore 추가, 비밀은 환경변수로 참조, 단일 명령 대신 패턴 단위 승인이다.
Claude Code를 쓰는 팀이라면 오늘 바로 저장소와 git 히스토리에서 .claude 폴더를 검색하고, MariaDB 접속 정보처럼 명령에 직접 넣은 비밀번호가 없는지 점검해야 한다.

detail: Rails가 Active Storage의 치명적 취약점(GHSA-f3w6-w445-fwh9, CVSS 9.8)을 공개하고 패치를 배포했다. GMO Flatt Security의 RyotaK가 HackerOne으로 제보했다.
- 업로드된 SVG가 분석 과정에서 ImageMagick의 MSL 코더에 도달해, 파일을 첨부하는 것만으로 공격이 성립한다. Disk 서비스를 쓰는 앱은 임의 파일 읽기도 가능하다.

- 수정 버전은 8.1.4.1과 8.0.5.2이며, 8.0 미만은 지원 종료라 패치가 없다. Rails 8.0 보안 지원도 11월 7일로 끝났다.
- 업그레이드가 어렵다면 시스템 ImageMagick policy.xml에서 MSL, Ghostscript 코더, gs delegate를 차단하고, Disk 서비스 사용 시 secret_key_base 등 비밀을 교체해야 한다.
Rails를 쓰지 않더라도 Spring 서비스에서 업로드 이미지를 ImageMagick으로 처리한다면 같은 원리의 공격이 가능하니, 서버의 ImageMagick 정책을 점검할 만하다.
